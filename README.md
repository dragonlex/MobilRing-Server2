# MobilRing-Server2

Серверная часть MobilRing: читает объявления из Firebase Realtime Database, ищет пары
«пропажа ↔ находка» и записывает их в узел `matches`. Приложение
[MobilRing](https://github.com/dragonlex/MobilRing) показывает эти пары в «Уведомлениях».
Ещё здесь живёт подсказка описаний для формы заявки.

Сначала пары оценивает эвристика (нормализация русского текста, синонимы, стемминг, числа,
цвета), спорные проверяет локальная языковая модель. Без модели сервис тоже работает —
по более высокому порогу.

---

## Запуск

Нужны Python 3.10+, `requests` и локальная модель. Проще всего через `llama-server.exe`:

```powershell
.\start-all.ps1        # модель, assist.py и matcher.py в отдельных окнах
```

По отдельности:

```powershell
.\start-llama.ps1      # модель на порту 5001
.\start-assist.ps1     # подсказки описаний, порт 5002
.\start-matcher.ps1    # поиск совпадений в цикле
```

Полезные режимы поиска:

```powershell
.\start-matcher.ps1 -Once      # один проход и выход
.\start-matcher.ps1 -DryRun    # показать пары, ничего не записывая
.\start-matcher.ps1 -NoLlm     # только эвристика
```

Альтернатива — KoboldCpp: `.\start-kobold.ps1` вместо `start-llama.ps1`.

## Установка KoboldCpp и модели

Ставится одним скриптом: качает KoboldCpp с GitHub и модель с Hugging Face (~5,5 ГБ).

```powershell
.\setup-kobold.ps1
.\setup-kobold.ps1 -SkipModel      # только KoboldCpp
.\setup-kobold.ps1 -SkipKobold     # только модель
```

Прерванную загрузку можно запустить снова — скрипт продолжит с того же места.
`.auth.json`, `ai\` и `models\` в репозиторий не попадают.

## Подсказка описаний

`assist.py` держит живую подписку на узел `assist` в базе. Приложение кладёт туда
заявку `status=pending` и подписывается на тот же ключ, сервис замечает её,
генерирует текст и дописывает в эту же запись `text` и `status=done`.
Приложение забирает текст, показывает «ОК», удаляет заявку и отписывается.
Прямого HTTP-соединения между телефоном и компьютером больше нет — нужен только интернет.

Описание всегда не длиннее 110 слов (`assist.max_words` в `config.json`): лимит
прописан в промпте и ещё раз проверяется на выходе.

Для ручной проверки остался HTTP-эндпоинт на порту 5002 (можно отключить подписку флагом
`--no-db`):

```powershell
curl.exe -s -H "Content-Type: application/json" `
  --data '{\"title\":\"рюкзак синий\",\"category\":\"рюкзак и сумка\"}' `
  http://127.0.0.1:5002/describe
```

Если модель недоступна, при `fallback_without_llm = true` сервис вернёт шаблонное описание.

## Как принимается решение

1. Закрытые заявки и уже найденные пары отбрасываются.
2. Пара получает оценку 0..1 по названию, описанию, месту и общей схожести текста.
3. Пары ниже `min_score` отбрасываются, остальные уходят в модель.
4. Пара записывается, если модель дала уверенность не ниже `llm_min_confidence`.
   Без модели — по эвристике.

Приложение читает из `matches` только `lostId`, `findId` и `createdAt`, остальное — для отладки.

## Доступ к базе

Правила Firebase требуют авторизации. Скрипт один раз создаёт служебного анонимного
пользователя и хранит refresh-токен в `.auth.json`; если файл удалить, создастся новый.
